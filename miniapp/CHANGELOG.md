## 1.0.32 · 2026-11-25

**修设置页二级弹窗内容超出后不能滑动**
- 根因：`.panel` 只有 `max-height: 82vh`，里面的 `scroll-view` 靠 `flex:1` 撑高——在 WebView 里 flex 子项拿不到确定高度，scroll-view 就退化成内容高度并整体被面板裁掉，于是「动作与 AI」「数据」这类长面板底部内容看不到也滑不动。
- 改法：内容外面套一层 `.p-in`，打开面板后量它的实际高度，取 `min(内容高, 0.82×windowHeight - 头部 - 安全区)` 写进 scroll-view 的 `style height`；scroll-view 有确定高度就正常滚。`.p-b` 改为 `flex: 0 0 auto`。
- 每个面板打开/切换都会重新量一次（`fitPanel()`，90ms 后量，避开首帧布局未完成）。

## 1.0.31 · 2026-11-25

**修「上传本机后仍显示待推 N」**
- 根因：脏队列（`selfagent_dirty_v1`）留着「本机已经没有这个实体」的键。上传时 `plan()` 只挑仍然存在的条目打包，这些键永远发不出去、也永远清不掉，于是「已同步 · 待推 12」一直挂着。
- 新增 `store.pruneDirty()`：按本机 train.records / train.cardio 的 uid、logs 的 id 过滤脏键，删掉的/合并掉的记录直接出队。推送前、状态查询前、设置页刷新前都会先清一次。
- 待推口径统一成一个来源：`sync.status().pending`（内部先 prune），设置页不再自己数三个数组。
- 上传按钮：成功才弹「已上传 · N 包」；有残留会说「已上传 · 待推 N」；失败改为弹窗给出云函数返回的错误，不再只弹一个「上传失败」。
- 结果：脏键全是历史残留时，进设置页即变回「已同步 · 时间」，不用再点上传。

## 1.0.26 · 2026-11-25

**修圆环三态状态机：ready 归零、继续计时、重置下放**
- Bug A：进新组 / 重进页面时 `mmss` 会带着上一组或上次会话的残留值直接开跑。改为每组进入一律 `stage=ready`、`mmss=0:00`、`_workStart=0`，点环才开始；重进只恢复「做过哪几组」，秒表值不带入。

- Bug C：环上的长按不再承担「完成本组」（原生拖拽判定会吞长按），完成只走大按钮 / 组行打勾。
- 重置改由暂停态承接：暂停时环内下方出现「重置本组」小字链接 → 点击后绿弧蓄能 800ms → 执行（蓄能期间点环取消），重置后回到 `ready 0:00`。双击重置取消，避免误触丢数据。
- 顶部汇总口径：动作 x/y 与组数统一取同一份 `setsDoneAll/setsTotalAll`，组百分比按组算。

## 1.0.20 · 2026-11-24

**修复：息屏/切后台后本组计时停在离开前的秒数**
- 根因两层：① 小程序退到后台后 `setInterval` 被挂起，画面不再刷新；② 1.0.19 里 `onHide` 记 `_hideAt`、`onShow` 又把这段时长从 `_workStart` 平移掉，等于主动把后台时间剔除了。
