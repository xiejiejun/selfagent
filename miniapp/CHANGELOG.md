## 1.0.44 · 2026-11-25

**自定义动作的图：图卡、详情都要出；动作本体和图片一起进云库**
- 原因一：训练页图卡只认 4 位数字 exId（库内动作），自定义动作 id 是 `my…`，`withImg / warmGrid / fillGrid` 全被过滤掉，只能显示部位占位字。
- 原因二：动作库卡片与详情都拿 `gifMigrate` 的 media_map 去查图，自定义动作不在那张表里，查不到就白块；详情里又因为「自定义跳过短片」时把 `clipReady` 置真，海报 `<image>` 的条件 `!clipReady` 直接把它藏了。
- 原因三：自定义动作的图如果当时云上传失败，只剩 `wxfile://` 临时路径；重启后临时文件失效，图就没了；而且只在 `trainmeta` 快照里同步，没有立即上行，换机容易看不到。
- 改法：
  - 训练页：`withImg` 对有 `my…` 的卡直接取 `train.custom` 里的图，`https/http` 与本地路径直接用，`cloud://` 走 `resolveCustImg` 换临时链接；`warmGrid/fillGrid` 拆成「库动作走映射、自定义走自带图」；`gridImgOk` 允许缓存 `my…` 的图。
  - 动作库：`fillImages` 把 `my…` 拆出来走 `resolveCustPoster`，卡片直接用自定义图；详情海报同样解析；自定义不查短片索引，也不再把 `clipReady` 置真，海报正常显示。
  - 自定义动作页：保存时若图还是本机临时路径，先补传云存储换成 fileID 再落库；进入该页时自动把老数据里只有临时路径的图补传；`actions.saveCustom/removeCustom` 标脏后立刻 `sync.flush()`，不再只等防抖。
  - 云库侧：自定义动作随 `trainmeta` 快照写入 `snapshots` 集合，图片本体在云存储 `custom/` 下，换设备拉 `syncPull` 即可还原。
- 验证（模拟器，冷启动；注入一条 `my_test1` 自定义卷腹 + 当天 3 组）：训练页图卡该卡 `img` 为图片地址、截图可见；动作库卡片 `fileID` 为同一地址、`mine=true`；详情 `fileID` 有值且 `clipReady=false`，海报正常渲染（`t9/h5-custom-detail.png`、`h6-train-grid-bottom.png`）。测试数据随后已从本机清除。

## 1.0.43 · 2026-11-25

**修「问今天，AI 拿近 30 天汇总回答」**
- 原因：`contextText()` 里只有「近 N 天训练天数 / 总容量 / 部位分布 / 按容量排的动作 Top5 / 7 天每天的总组数」，没有「今天到底做了哪几个动作」。模型被问「今天侧重点」时，手里只有 30 天汇总，只能拿汇总答。提示词也没有时间范围规则。
- 改法：
  - 上下文首行改成【今天 MM-DD】，直接列当天完成的动作名 + 完成组数 + 代表重量（自重不写重量），末尾带当天总组数/总容量；当天没练给「无记录」。
  - 新增【每日明细·近 7 天】：每天一行动作清单（最多 8 个，按组数排），问「昨天/某天」也有据可依。
  - 30 天口径统一标注「只作趋势」，避免被当成某一天的数据。
  - system prompt 增加时间范围硬约束：问「今天」只用【今天】，问「昨天/某天」只用【每日明细】对应那天，问「最近一周」才用 7 天汇总；回答开头写清用的是哪天。
- 验证（模拟器，冷启动，真机同源记录）：上下文输出「【今天 11-25】杠铃卧推 3组/30kg…分腿跳 1分 · 共 18 组 / 6150kg」；问「你觉得我今天练的动作侧重点都在哪」→ 回答「今天的数据显示…胸 45% 组数、背 33%、三头/肩 17%、腿 5%」，全部来自当天 8 个动作，未再引用 30 天累计。

## 1.0.42 · 2026-11-25

**修「今天练了悬垂卷腹，分析页却判腰腹 0 kg、问 AI 说没练核心」**
- 原因一（口径）：`partStats` 只累加 `it.volume`。自重动作（悬垂卷腹、平板、引体）容量恒为 0，腰腹就被统计成 `0 组/0 kg`，短板卡直接输出「腰腹 只占容量 0%」。
- 原因二（标签）：历史记录里「悬垂卷腹」的 `part` 被写成背 / 胸 / 肩 / 上腿 / 其他（自建动作与导入数据都有），即使加了组数也归不到腰腹。
- 原因三（提示词）：`contextText` 给模型的只有「部位 X kg」和按容量排的 Top5 动作，自重动作全被容量排序挤出列表；system prompt 也没说「容量 0 ≠ 没练」，模型只能回答没练核心。
- 改法：
  - `engine.partStats` 增加 `sets`（完成组数，排除热身），容量与组数一起返回；`sets` 按 `it.done` 累计，自重动作也不再丢。
  - 新增 `engine.partForName(train, name, fallback)`：动作库同名动作的部位优先；自建动作取 `custom.p`；名称含核心词（卷腹 / 平板 / 举腿 / 仰卧起坐 / 侧屈 / 两头起 / 登山跑 / 死虫）一律归腰腹；否则用原 `part`。`stDayItems` 与 `actions.saveStrength` 都走它，历史脏标签在读数时自动归位，编辑保存也会写正。
  - 分析页改成组数口径：部位分布条按组数占比（标题注明「自重也计入」），主力/短板按组数百分比，依据行显示「N 组 · X kg」。

## 1.0.20 · 2026-11-24

**修复：息屏/切后台后本组计时停在离开前的秒数**
- 根因两层：① 小程序退到后台后 `setInterval` 被挂起，画面不再刷新；② 1.0.19 里 `onHide` 记 `_hideAt`、`onShow` 又把这段时长从 `_workStart` 平移掉，等于主动把后台时间剔除了。
